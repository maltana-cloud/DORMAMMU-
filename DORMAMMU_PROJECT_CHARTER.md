# DORMAMMU PROJECT CHARTER — CANONICAL

This is the concise project-level charter for DORMAMMU. The detailed master architecture and operating rules remain in `DORMAMMU_CHARTER.md`.

## Identity

DORMAMMU is the permanent product/project identity: a general-purpose autonomous intelligence and ecosystem platform, not a single-purpose bot or collection of unrelated agents. The historical `devintel/` Python namespace is retained temporarily only for backward-compatible imports.

## Mission

DORMAMMU continuously turns verified understanding into useful action and sustainable value while preserving truth, safety, owner control, modularity, resilience, and future extensibility.

`OBSERVE → DISCOVER → UNDERSTAND → VERIFY → IDENTIFY DEMAND → CREATE → DISTRIBUTE → CREATE AWARENESS → MONETIZE → MEASURE → EVOLVE`

## Architecture

One coordinated system, many specialized capabilities. Core contracts and authority boundaries are protected; capability implementations remain replaceable and extensible.

Every consequential action follows:

`REQUEST → UNDERSTAND → PLAN → PERMISSION CHECK → SECURITY CHECK → EXECUTE → VERIFY → RECORD`

Intelligence, capability, model output, external content, and discovered resources never grant authority by themselves.

## Locked Foundation, Open Capability Surface

DORMAMMU is locked in principles, authority boundaries, security, truth/provenance, owner control, recovery protections, and architectural direction — not in future functionality.

Future domains, agents, models, tools, providers, platforms, datasets, compute resources, education, media/music/film, games, languages, business systems, and capabilities not yet known may be added without redesigning the protected foundation.

New capabilities should be additive, modular, isolated, versioned, tested, backward-compatible wherever practical, and independently deployable wherever practical.

## Capability Gap Rule

When a goal needs something DORMAMMU does not have:

`GOAL → REQUIREMENTS → CAPABILITY CHECK → GAP DETECTION → SCOUT → EVALUATE → INTEGRATE/BUILD/QUEUE → VERIFY → REGISTER`

Discovery never equals trust, permission, installation, or execution. External capabilities must be evaluated for provenance, licensing/terms, dependencies, security, compatibility, performance, resource requirements, cost, permissions, maintainability, and rollback.

Prefer:

`EXISTING → REUSE → TRUSTED OPEN SOURCE → FREE PROVIDER → LOCAL COMPUTE → BUILD/FINE-TUNE → LOW-COST PAID → EXPENSIVE`

## Truth, Security and Owner Control

External information and model output are untrusted until independently validated. Important claims require appropriate evidence/provenance; contradictions and uncertainty must be preserved when unresolved.

Security follows:

`DETECT → CONTAIN → ISOLATE → UNDERSTAND → RECOVER → VERIFY → LEARN`

Owner identity, authority, secrets, trust anchors, permissions, audit integrity, containment, and recovery are protected foundations. No unrestricted self-modification, secret backdoor, CAPTCHA/verification bypass, platform-control bypass, or unrestricted withdrawal-enabled financial authority.

## Agents, Models and Resources

Agents and models are workers/capabilities. CPU, GPU, RAM, storage, network, APIs, datasets, and providers are resources/capabilities. None is an authority.

Provider/resource failure must use legitimate fallback, queueing, or safe degradation rather than circumvention.

## Continuous Engineering

When an owner assigns a DORMAMMU engineering objective, builders should continue through safe available work:

`INSPECT → PLAN → IMPLEMENT → TEST → DEBUG → REPAIR → INTEGRATE → SECURITY CHECK → DOCUMENT → COMMIT → CI → VERIFY → CHECKPOINT → CONTINUE`

Pause only when authorization, credentials/OAuth, spending, critical security judgment, irreversible external action, unavailable required resources, or material ambiguity genuinely requires the owner.

## Completion

Work is complete only when implementation, tests, security/permission boundaries, integration, documentation, status, and repository continuity support the claim. Every meaningful contributor must leave a truthful checkpoint.

**DORMAMMU is locked in principles, not frozen in capability.**
